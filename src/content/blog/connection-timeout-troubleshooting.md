# 连接超时与网络异常全流程排查指南：从客户端日志到本地 DNS 调优

在日常使用网络代理工具时，偶尔会遇到网页提示“ERR_CONNECTION_TIMED_OUT”、“代理服务器无响应”或客户端连接日志中刷新出大量的红色警告。

遇到连接异常时，盲目重启电脑往往收效甚微。本文将为您提供一份标准化的**排查流程图与日志报错速查手册**，帮助您在 3 分钟内准确定位问题根源。

## 二、四大最常见报错日志及解决对策

### 报错 1：`context deadline exceeded` 或 `i/o timeout`
- **现象描述：** 客户端尝试与目标服务器建立 TCP 或 TLS 连接，但在设定的超时阈值内未收到 SYN-ACK 回应；
- **排查原因：**
  1. 当前选择的出口节点正在进行临时网络维护；
  2. 本地运营商到代理入口节点的公网链路突发丢包；
- **解决对策：**
  - 在客户端中切换到同地区的其他备用节点（例如从香港 01 切换到香港 02）；
  - 点击客户端中的「延迟测试」按钮，剔除超时节点。

### 报错 2：`tls: bad certificate` 或 `certificate has expired or is not yet valid`
- **现象描述：** TLS 握手失败，证书无效；
- **排查原因：** **90% 的情况是因为电脑/手机本地系统时间与网络标准时间不一致！** 加密算法校验时，如果本地系统时间偏差过大，就会判定证书尚未生效或已过期；
- **解决对策：**
  - **Windows：** 右键任务栏右下角时间 ->「调整日期和时间」-> 点击「立即同步」；
  - **macOS / iOS / Android：** 确保在系统设置中勾选了「自动设置时间与时区」。

### 报错 3：`remote error: tls: handshake failure`
- **现象描述：** 客户端与代理服务器未能就 TLS 协议版本或加密套件（Cipher Suite）达成一致；
- **排查原因：** 客户端版本过于老旧，不支持现代加密标准；
- **解决对策：** 请前往[客户端下载中心](/download/)下载最新版本的 Clash Verge Rev、Mihomo Party 或 Shadowrocket。

### 报错 4：`EOF` 或 `connection reset by peer`
- **现象描述：** 远端服务器主动强行切断了当前 TCP 连接；
- **排查原因：** 访问特定境外敏感域名时，本地 DNS 解析遭到了污染，请求被错误重定向到了不存在的 IP；
- **解决对策：**
  - 在客户端中将 DNS 模式修改为 **Fake-IP 模式**；
  - 开启客户端的 **远程 DNS 解析（Remote DNS）**，确保域名解析完全在海外节点侧完成。

## 三、高级优化：调优本地 DNS 与 TUN 配置

1. **避免 DNS 泄露：**
   在 Clash Verge Rev 的配置中，推荐将国内 DNS 服务器设置为公共低延迟地址（如 `223.5.5.5` 与 `119.29.29.29`），而境外 DNS 设定为纯净的加密 DNS（如 `https://1.1.1.1/dns-query`）；
2. **正确开启 TUN 模式：**
   对于命令行或游戏用户，遇到代理不生效时，请务必在客户端「设置」中安装并启动 TUN 虚拟网卡驱动，这将直接在网络层捕获全部数据包。
